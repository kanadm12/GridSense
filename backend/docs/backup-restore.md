# GridSense Backup and Disaster Recovery Guide

## Backup Strategy

### What to Back Up
1. **PostgreSQL Database** - All user data, meters, readings, aggregates
2. **ML Models** - Trained Prophet and IsolationForest models (optional, can retrain)
3. **Environment Configuration** - `.env` file and secrets
4. **Redis Data** - Job queue state (optional, transient data)

### Backup Frequency
- **Database**: Daily full backup + hourly incremental
- **ML Models**: Weekly or after training (less critical)
- **Configuration**: On every change

## PostgreSQL Backup

### Manual Backup
```bash
# Full database dump
docker compose exec db pg_dump -U postgres gridsense_prod > backup_$(date +%Y%m%d_%H%M%S).sql

# Compressed backup
docker compose exec db pg_dump -U postgres gridsense_prod | gzip > backup_$(date +%Y%m%d_%H%M%S).sql.gz

# Backup with custom format (supports parallel restore)
docker compose exec db pg_dump -U postgres -Fc gridsense_prod > backup_$(date +%Y%m%d_%H%M%S).dump
```

### Automated Daily Backup Script

Create `scripts/backup.sh`:
```bash
#!/bin/bash
set -e

BACKUP_DIR="/var/backups/gridsense"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="$BACKUP_DIR/gridsense_$DATE.dump"
RETENTION_DAYS=30

# Create backup directory
mkdir -p $BACKUP_DIR

# Perform backup
docker compose exec -T db pg_dump -U postgres -Fc gridsense_prod > $BACKUP_FILE

# Compress
gzip $BACKUP_FILE

# Delete old backups (keep last 30 days)
find $BACKUP_DIR -name "gridsense_*.dump.gz" -mtime +$RETENTION_DAYS -delete

# Verify backup integrity
gunzip -c $BACKUP_FILE.gz | head -n 1 | grep -q "PostgreSQL"

echo "Backup completed: $BACKUP_FILE.gz"
```

### Schedule with Cron
```bash
# Add to crontab
crontab -e

# Daily backup at 2 AM
0 2 * * * /path/to/gridsense/scripts/backup.sh >> /var/log/gridsense-backup.log 2>&1
```

### Backup to Cloud Storage

**AWS S3:**
```bash
#!/bin/bash
BACKUP_FILE="backup_$(date +%Y%m%d_%H%M%S).dump.gz"
docker compose exec -T db pg_dump -U postgres -Fc gridsense_prod | gzip > $BACKUP_FILE
aws s3 cp $BACKUP_FILE s3://gridsense-backups/db/$BACKUP_FILE
rm $BACKUP_FILE
```

**Google Cloud Storage:**
```bash
#!/bin/bash
```

## Database Restore

### From SQL Dump
```bash
# Stop API and workers (prevent writes during restore)
docker compose stop api worker scheduler

# Drop and recreate database (CAUTION: Data loss!)
docker compose exec db psql -U postgres -c "DROP DATABASE gridsense_prod;"
docker compose exec db psql -U postgres -c "CREATE DATABASE gridsense_prod;"

# Restore from backup
gunzip -c backup_20260818_120000.sql.gz | docker compose exec -T db psql -U postgres gridsense_prod

# Restart services
docker compose start api worker scheduler
```

### From Custom Format Dump
```bash
# Stop services
docker compose stop api worker scheduler

# Restore (parallel restore with 4 jobs)
gunzip -c backup_20260818_120000.dump.gz | docker compose exec -T db pg_restore -U postgres -d gridsense_prod -j 4

# Restart services
docker compose start api worker scheduler
```

## ML Model Backup

### Backup Models
```bash
# Models are stored in backend/app/models/*.joblib
tar -czf models_backup_$(date +%Y%m%d).tar.gz backend/app/models/*.joblib 2>/dev/null || true

# Copy to backup location
mv models_backup_*.tar.gz /var/backups/gridsense/models/
```

### Restore Models
```bash
# Extract to models directory
cd backend/app/models
tar -xzf /var/backups/gridsense/models/models_backup_20260818.tar.gz
```

**Note**: ML models can be regenerated by retraining. Backup is optional.

## Point-in-Time Recovery (PITR)

### Enable WAL Archiving (PostgreSQL)

Add to `postgresql.conf`:
```
wal_level = replica
archive_mode = on
archive_command = 'test ! -f /var/lib/postgresql/wal_archive/%f && cp %p /var/lib/postgresql/wal_archive/%f'
```

### Base Backup with WAL
```bash
# Create base backup
docker compose exec db pg_basebackup -U postgres -D /var/lib/postgresql/basebackup -Ft -z -P

# Archive WAL files continuously
# PostgreSQL will use archive_command to copy WAL files
```

### Restore to Point in Time
```bash
# 1. Restore base backup
# 2. Copy WAL files to pg_wal directory
# 3. Create recovery.conf with recovery_target_time
# 4. Start PostgreSQL - it will replay WAL files to target time
```

**Note**: PITR setup is advanced. Consider managed PostgreSQL services (RDS, Cloud SQL) for production.

## Disaster Recovery Scenarios

### Scenario 1: Database Corruption
1. Stop all services: `docker compose down`
2. Restore from latest backup (see above)
3. Apply any missed migrations: `alembic upgrade head`
4. Start services: `docker compose up -d`
5. Verify health and data integrity

### Scenario 2: Accidental Data Deletion
1. If recent (< 1 hour): Restore from most recent backup
2. If older: Use PITR to restore to time before deletion
3. Compare restored data with current state
4. Merge or replace as needed

### Scenario 3: Complete Infrastructure Loss
1. Provision new infrastructure
2. Deploy GridSense from git repository
3. Create database and apply schema: `alembic upgrade head`
4. Restore database from backup
5. Restore ML models (or retrain)
6. Configure environment variables
7. Start services and verify health

### Scenario 4: Malicious Attack
1. Immediately stop all services
2. Analyze logs for breach entry point
3. Restore from backup taken before attack
4. Apply security patches
5. Rotate all secrets (DATABASE_URL, SECRET_KEY, API keys)
6. Review and harden security (firewall, access control)
7. Restart services with new configuration

## Backup Retention Policy

### Recommended Retention
- **Daily Backups**: Keep for 30 days
- **Weekly Backups**: Keep for 90 days
- **Monthly Backups**: Keep for 1 year
- **Quarterly Backups**: Keep for 3 years (compliance)

### Retention Script
```bash
#!/bin/bash
BACKUP_DIR="/var/backups/gridsense"

# Keep daily backups for 30 days
find $BACKUP_DIR/daily -name "*.dump.gz" -mtime +30 -delete

# Keep weekly backups for 90 days
find $BACKUP_DIR/weekly -name "*.dump.gz" -mtime +90 -delete

# Keep monthly backups for 365 days
find $BACKUP_DIR/monthly -name "*.dump.gz" -mtime +365 -delete
```

## Testing Backups

### Monthly Backup Test
```bash
#!/bin/bash
# Restore to test database and verify

# 1. Create test database
docker compose exec db psql -U postgres -c "CREATE DATABASE gridsense_test_restore;"

# 2. Restore latest backup
LATEST_BACKUP=$(ls -t /var/backups/gridsense/*.dump.gz | head -1)
gunzip -c $LATEST_BACKUP | docker compose exec -T db pg_restore -U postgres -d gridsense_test_restore

# 3. Run validation queries
docker compose exec db psql -U postgres gridsense_test_restore -c "
SELECT COUNT(*) as user_count FROM users;
SELECT COUNT(*) as meter_count FROM meters;
SELECT MAX(timestamp) as latest_reading FROM readings;
"

# 4. Clean up
docker compose exec db psql -U postgres -c "DROP DATABASE gridsense_test_restore;"

echo "Backup test completed successfully"
```

## Backup Monitoring

### Check Backup Success
```bash
# Verify backup file exists and is recent
LATEST_BACKUP=$(ls -t /var/backups/gridsense/*.dump.gz | head -1)
AGE_HOURS=$(echo "( $(date +%s) - $(stat -c %Y $LATEST_BACKUP) ) / 3600" | bc)

if [ $AGE_HOURS -gt 26 ]; then
  echo "WARNING: Latest backup is $AGE_HOURS hours old"
  # Send alert
fi
```

### Alert on Backup Failure
```bash
# Add to backup script
if [ $? -eq 0 ]; then
  echo "Backup successful" | mail -s "GridSense Backup OK" admin@example.com
else
  echo "Backup failed!" | mail -s "GridSense Backup FAILED" admin@example.com
fi
```

## Security Considerations

- Encrypt backups at rest: `gpg --encrypt backup.dump.gz`
- Store backups in separate location (different datacenter/region)
- Restrict backup file access: `chmod 600 backup.dump.gz`
- Use secure transfer: SFTP, SCP, or cloud storage with encryption
- Audit backup access logs quarterly
- Test restore procedure quarterly
- Document recovery time objective (RTO) and recovery point objective (RPO)

## Compliance

### Data Retention for Energy Data
- Check local regulations (e.g., Australian Energy Retail Law)
- Typically: Keep energy consumption data for 2-7 years
- Anonymize or delete personal data on user request (GDPR, Privacy Act)

### Audit Trail
- Log all backup operations with timestamps
- Log all restore operations with reason and operator
- Store audit logs separately from application logs
